# Двойное Рождество — сайт-приглашение с заявками в Telegram

Статический сайт (`public/`) и небольшой сервер на Node.js + Express (`server.js`).
Посетитель заполняет форму → браузер отправляет `POST /api/lead` → сервер проверяет данные и шлёт красивое сообщение вашему боту → оно приходит вам в Telegram.

```
.
├── public/          сайт: index.html, styles.css, main.js, og.jpg, шрифты, иконки, фон «мираж» (assets/mirage), раздел 7
├── server.js        сервер: отдаёт сайт, принимает заявки (POST /api/lead), GET /api/health
├── package.json
├── .env.example     шаблон секретов — копия называется .env
└── .gitignore       .env и node_modules в git не попадают
```

## 1. Токен бота и chat_id

1. В Telegram откройте **@BotFather** → `/newbot` → задайте имя → получите токен вида `123456789:AAH...`.
2. Выберите, куда приходить заявкам:
   - **личный чат** — откройте своего бота и нажмите **Start** (или напишите ему любое сообщение);
   - **группа** — добавьте бота в группу и напишите в ней любое сообщение.
3. Откройте в браузере (подставьте свой токен):
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
4. В ответе найдите `"chat":{"id": ...` — это и есть **chat_id**: например `123456789` (личный чат) или `-1001234567890` (группа, число отрицательное).

Если в ответе `"result":[]` — напишите боту ещё раз и обновите страницу. Если у бота настроен webhook, `getUpdates` не работает.

## 2. Запуск

Нужен [Node.js](https://nodejs.org) 18 или новее: скачайте версию **LTS**, установите (все настройки по умолчанию) и откройте терминал заново. Проверка: `node -v` покажет номер версии. Терминал в Cursor: меню Terminal → New Terminal.

```bash
npm install
cp .env.example .env        # в Windows cmd: copy .env.example .env
# откройте .env и впишите TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID
npm start
```

Откройте <http://localhost:3000> — сайт и API работают на одном адресе, CORS не нужен.
Для разработки с автоперезапуском: `npm run dev`.

### Фронт и бэк на разных портах (CORS)

Например, сайт открыт через Live Server / `npx serve public -l 5500`, а сервер работает на порту 3000:

1. В `.env`: `ALLOWED_ORIGINS=http://localhost:5500` (адреса через запятую, без `/` на конце).
2. В `public/index.html` впишите адрес сервера: `<meta name="api-base" content="http://localhost:3000">`.

Если `ALLOWED_ORIGINS` пуст, чужим сайтам доступ к API закрыт.

## 3. Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | да | куда присылать заявки |
| `PORT` | нет | порт сервера (по умолчанию 3000; хостинги задают сами) |
| `TRUST_PROXY` | на хостинге — да | сколько прокси стоит перед сервером, обычно `1`; нужен для настоящего IP и лимита по IP |
| `ALLOWED_ORIGINS` | нет | сайты с других адресов, которым разрешено слать заявки (CORS) |
| `LEAD_COOLDOWN_SECONDS` | нет | не чаще 1 заявки с IP за N секунд (по умолчанию 30) |

## 4. Деплой

Сначала запомните: **чисто статический хостинг (загрузка архива с сайтом) заявку принять не может** — для этого нужен сервер на Node.js. Без него форма честно напишет «Приём заявок на этой странице пока не подключён» и предложит позвонить или написать в Telegram.

### Вариант A — всё на одном Node-хостинге (проще всего)

**Render** (есть бесплатный тариф):

1. Загрузите проект на GitHub (`.env` туда не попадёт — он в `.gitignore`).
2. Render → New → **Web Service** → выберите репозиторий. Build command: `npm install`, Start command: `npm start`.
3. В разделе Environment добавьте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `TRUST_PROXY=1`.
4. Deploy. Сайт и форма заработают по адресу вида `https://имя.onrender.com`.

На бесплатном тарифе сервис «засыпает» без посетителей — первое открытие может занять около минуты. Railway и Fly.io настраиваются так же: команда запуска `npm start`, те же переменные.

**Свой сервер (VPS, Ubuntu):**

```bash
git clone <ваш-репозиторий> invite && cd invite
npm ci --omit=dev
cp .env.example .env && nano .env        # токен, chat_id и TRUST_PROXY=1
sudo npm i -g pm2 && pm2 start server.js --name invite && pm2 save && pm2 startup
```

nginx перед сервером (затем `sudo certbot --nginx -d ваш-домен` для https):

```nginx
server {
    server_name ваш-домен;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### Вариант B — сайт на статическом хостинге, сервер отдельно

1. Сервер задеплойте как в варианте A — на нём будет работать `/api/lead`.
2. В `public/index.html` впишите его адрес: `<meta name="api-base" content="https://имя.onrender.com">`.
3. На сервере задайте `ALLOWED_ORIGINS=https://адрес-вашего-сайта`.
4. Папку `public/` загрузите на статический хостинг.

### После публикации

В `public/index.html` замените `og.jpg` в тегах `og:image` и `twitter:image` на полный адрес (`https://ваш-сайт/og.jpg`) — иначе превью ссылки в мессенджерах не подтянется.

## 5. Проверка без браузера

```powershell
Invoke-RestMethod http://localhost:3000/api/lead -Method Post -ContentType 'application/json' `
  -Body '{"name":"Anna","phone":"+375291234567","message":"test"}'
```

Ответ `ok : True` — сообщение пришло в Telegram. Повтор в течение 30 секунд вернёт `429`, пустое имя или короткий номер — `400`.

## 6. Если что-то не так

| Симптом | Причина |
|---|---|
| `node` или `npm` «не распознано как имя командлета» | Node.js не установлен (или терминал открыт до установки) — установите LTS с nodejs.org и откройте терминал заново |
| PowerShell: «выполнение сценариев отключено в этой системе» при `npm …` | один раз выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` и откройте терминал заново — или пишите `npm.cmd` вместо `npm` |
| Сервер не стартует: «Не заданы TELEGRAM_BOT_TOKEN…» | нет файла `.env` или в нём пустые значения |
| В логе `Telegram API ответил 401` | неверный токен |
| В логе `chat not found` | неверный `chat_id`, или вы не нажали Start у бота / бот не добавлен в группу |
| В логе `403` | бот заблокирован или удалён из чата |
| Посетитель получает «Слишком много заявок подряд», хотя до этого никто не писал | на хостинге не задан `TRUST_PROXY=1` — у всех посетителей один IP |
| В консоли браузера ошибка CORS | адрес страницы не указан в `ALLOWED_ORIGINS` (нужен вместе с `http://`/`https://`, без `/` на конце) |

## 7. Фон первого экрана («мираж»)

В небе над холмами по очереди проступают святые места бахаи: Усыпальница Баба (два кадра), Храм Лотоса, вход в Усыпальницу Бахауллы и Храм бахаи в Уилметте. Каждая сцена — две прозрачные картинки в `public/assets/mirage/`: чёткая (`имя.webp`) и размытая дымка (`имя-haze.webp`). Всего около 740 КБ; они подгружаются после загрузки страницы и не задерживают первый показ.

- Порядок, сторона, размер и яркость сцен — в `public/index.html`, блок `<div class="mirage" id="mirage">`: `--i` очередь, `--sx` сдвиг по горизонтали, `--sz` размер, `--pk` яркость.
- Скорость — в `public/styles.css`, правило `.mirage{--slot:10s;--cyc:50s}`: слот на одну сцену и полный круг (слот × число сцен). Если сцен станет больше или меньше, поменяйте `--cyc`; переходы чуть ускорятся или замедлятся.
- Убрать мираж совсем — удалите блок `<div class="mirage" id="mirage">…</div>` из `index.html`.
- Анимация встаёт на паузу, когда первый экран не виден. При включённом «уменьшить движение» показывается одна тихая сцена без анимации, при экономии трафика фон не грузится.
- Замените картинки — увеличьте `VER` в `public/main.js` (`?v=2` на `?v=3`), иначе браузеры покажут старые из кэша.
- Авторы и лицензии (Wikimedia Commons, CC BY и CC BY-SA) указаны в подвале сайта и в `public/assets/mirage/CREDITS.txt`. Если добавите свои фотографии, допишите авторов туда же.

## Безопасность

- Токен и chat_id хранятся только в `.env` или в переменных окружения хостинга. В браузер они не попадают: сайт обращается лишь к `/api/lead`, а в Telegram ходит сервер.
- Если токен утёк — у @BotFather команда `/revoke`, затем обновите `.env`.
- От спама: лимит «1 заявка в 30 секунд с одного IP», скрытое поле-ловушка для ботов, проверка и ограничение длины всех полей на сервере, экранирование HTML в сообщении.
